Product line

Two products, one problem.

Plant data is usually stuck — locked behind a proprietary historian, or behind a twenty-year-old DCOM interface nobody wants to touch. One product gets history out. The other gets legacy servers onto a modern protocol.

Shipping

HistorianLink

OPC UA history · reports · dashboards · alarms

Connects as an OPC UA client to a plant historian — Siemens Process Historian, WinCC, or any compliant UA server — and turns its archive into something you can actually use. Browse the tag tree, pull raw history, resample it, and export to Excel or CSV with real quality codes attached.

  • History export jobs — raw reads resampled to any interval, millisecond timestamps, plain-English quality column, UTC or local toggle, metadata header block.
  • Scheduled reports — repeatable report definitions written to .xlsx, last five runs kept per report.
  • Live dashboards — tiles with current value and sparkline, polled only while someone is watching.
  • Alarm history — a satellite agent reads the WinCC message archive over OLE DB, the supported route when UA returns BadNotImplemented for event history.
  • Trend analyser — multi-tag chart with severity colouring, presets and a scrubbing ruler.
  • Three access levels — admin on loopback, engineer over TLS, read-only viewer.
  • Device trust — allow-list connections by IP, or IP + MAC with ARP verification.
  • Audit trail — logins, exports, config changes; no credentials, no stack traces.

OpcDaLink

OPC DA → OPC UA bridge

Sits in front of a legacy OPC DA server, connects to it as a DA client over DCOM, and re-publishes the whole address space as a modern OPC UA server. Point UaExpert, a new SCADA package, or HistorianLink at the UA endpoint and leave the old server exactly as it is.

  • Full address-space mirror — branches become folders, leaves become variables, item IDs carry through as string NodeIds.
  • Faithful type mapping — canonical VARIANT types to UA variant types, DA quality words to UA status codes, item timestamps as source timestamps.
  • Read and write — access rights map to node writability, with writes passed back through to DA.
  • Correct COM threading — a dedicated message-pumped STA thread, because that is the only way DA data-change callbacks ever arrive.
  • Big-server mode — feed it a tag list file and skip browsing entirely on servers with tens of thousands of items.
  • Built-in diagnostics — connection state and item count exposed as UA nodes, plus a web admin page.

Shared platform

Both products are built the same way.

Same installer, same service model, same licensing, same security posture. Learn one, you know both.

01 / SERVICE

Windows service + tray

Runs headless as a service and survives reboots. A tray icon gives operators start, stop and status without opening the admin UI or needing a login.

02 / INTERFACE

Browser-based admin

No client to roll out. The service hosts its own UI on a local port — the same dark, dense, keyboard-friendly interface shown in the screenshots above.

03 / SECURITY

Encrypted config at rest

Credentials and connection settings are encrypted with Windows DPAPI, tied to the machine. Nothing sensitive sits in plain text on disk.

04 / NETWORK

TLS where it matters

Network-facing endpoints run HTTPS with a minimum of TLS 1.2. Admin stays on loopback, where encrypting the traffic would buy nothing.

05 / LICENSING

Fully offline activation

A key tied to your customer ID, validated on the machine. No activation server, no internet, no phone-home — designed for air-gapped plant networks.

06 / DEPLOYMENT

Signed MSI install

A standard MSI your IT team can review, deploy and uninstall cleanly. Silent install supported for managed rollouts.
